# Shofe montaža

You film, Claude edits. Everything runs locally with Python + ffmpeg; transcription is free and offline (faster-whisper).
Talk to the user in Croatian. Scripts live in `scripts/` next to this file (the skill's base directory, called `<skill>` below).
On Windows use forward slashes and quote every path: `python "<skill>/scripts/render.py" "C:/Users/.../shofe_projekt"`. If `python` is not found, try `py -3`.

## First edit of a video

1. **Check setup** (once per session): `python "<skill>/scripts/doctor.py"`. If anything is `[!!]`, run it with `--popravi`, and if ffmpeg was just installed tell the user to restart Claude. The first line shows the Shofe version (`doctor.py --verzija` prints only that); tell it to the user when they ask which version they have or report a bug. Python packages come from `<skill>/requirements.txt`.
2. **Prepare clips**: `python "<skill>/scripts/prepare.py" <clips or folder> --out shofe_projekt [--format 9:16|16:9|1:1|4:5]`
   - Clips are joined in the given order (a folder → sorted by file name). Ask about the order only if the names don't make it obvious.
   - Default 9:16. Use 16:9 for "YouTube"/"dugi video". Landscape clips get centre-cropped; adjust with `--crop-x 0.3` (0 left … 1 right) after checking a frame. When landscape footage shows **people talking** (podcast, interview, two people in the car) and the format is narrower (9:16, 4:5, 1:1), use `kadar.py` instead (step 4b) so the frame follows whoever speaks.
   - Put the project folder next to the clips unless the user says otherwise.
3. **Transcribe**: `python "<skill>/scripts/transcribe.py" shofe_projekt` (default model large-v3-turbo, language hr). The first run downloads the model (~1.6 GB), so warn the user it will take a few minutes once. For speed on a weak laptop use `--model medium`. Other languages: `--jezik sr|bs|en|auto`.
4. **Speakers** (only when more than one person talks: podcast, interview, conversation, a guest): `python "<skill>/scripts/govornici.py" shofe_projekt` (after transcribe, before analyze/plan) → `govornici.json`. Runs on the CPU, ~7× faster than real time; the first run downloads two small models (~36 MB). If the user knows how many people talk, add `--broj N` (more reliable). Speakers are `G1`, `G2`… in order of first appearance; it prints a transcript by speaker — read it, work out who is who (e.g. the host introduces the guest), confirm with the user if unsure, then name them: `--imena "G1=Marko,G2=Ivan"` (instant, no re-analysis; names survive reruns). If one person was split into two, rerun with `--broj`; if two people were merged, rerun with `--broj` or `--prag 0.4` (lower → more speakers). After this, `plan.py` and `analyze.py` put the speaker on every segment (`"govornik"`), a segment never spans two speakers, and `transcript.txt` shows `Ime: tekst`. Skip it for a solo reel.
4b. **Frame follows the speaker** (landscape clips with faces → 9:16/4:5/1:1; after step 4 when several people talk, or right after transcribe for one person): `python "<skill>/scripts/kadar.py" shofe_projekt` → finds faces in the **original clips** (YuNet in OpenCV, CPU, ~10 frames/s analysed), decides who speaks when (speaker from `govornici.json` matched to the face whose lips move during that speaker's turns; without govornici.json: whose lips move most while someone talks), writes `kadar.json` and rebuilds `source.mp4` with a moving crop. Timing does not change: transcript, govornici.json, analiza.json and edit.json stay valid, so it can run at any point before render (`render.py` again afterwards). It prints the people (`O1` left …, with matched speaker) and the shots (`od–do`, person, `miruje`/`prati`, crop_x). Behaviour: a switch between people is a hard cut, never a pan; a shot lasts ≥ 1.5 s (a short "da" does not switch); the camera stays still while the face sways and follows smoothly only when the person moves; a voice with no face in the picture (off-camera) keeps the current shot; one person → always centred on them; no faces → the fixed `--crop-x` crop stays. Vertical clips are skipped.
   - Check with `render.py --kadar` (step 8) at a couple of speaker changes. Wrong person → usually the speakers are wrong: fix `govornici.py` (e.g. `--broj`), then rerun `kadar.py`. `--analiza` = only `kadar.json` + printout (video unchanged); `--vrati` = back to the fixed crop. Re-running `prepare.py` drops the tracking (run `kadar.py` again).
5. **Video map** (`analiza.json`): `python "<skill>/scripts/analyze.py" shofe_projekt` (after transcribe; ~8× faster than real time on a weak laptop, `--bez-slike` skips the picture part). It measures speakers' share (`govornici`, if govornici.json exists), silences, loudness (whole video + per segment), speech tempo (syllables/s), scene cuts, blurry/dark/overexposed shots and clip joins, and writes `analiza.txt`, a short readable summary. Segment numbers match `edit.json` (same `--pauza` as plan.py, default 0.3). Always run it for videos longer than ~3 min, podcasts and clip hunting; for a short reel it is optional but read its `Loši kadrovi` line.
   - Then **you** add the meaning, in `analiza.json` (rerunning analyze.py keeps these):
     - `teme`: `[{"od": s, "do": s, "naslov": "3–6 words", "sazetak": "one sentence"}]` — consecutive topics covering the talk, in source seconds (take them from the word times in `transcript.json` / segment times).
     - `trenuci`: `[{"od": s, "do": s, "vrsta": "hook|poanta|smijeh|emocija|savjet|citat|akcija|ostalo", "ocjena": 1-5, "opis": "why it is strong"}]` — the strongest moments: a promise/question that makes people stay (hook), the payoff, laughs, emotional or quotable lines, concrete tips. 5 = would open a reel with it. Quality over quantity (for 1 min ~2–4, for 60 min ~20–40).
   - Check with `python "<skill>/scripts/analyze.py" shofe_projekt --provjeri` (refreshes `analiza.txt`; on mistakes exits 1 and lists them — fix and rerun).
   - **Visual overview for the user**: analyze.py (and `--provjeri`) also writes `pregled.html` in the project folder — one offline page with the video, a zoomable timeline (loudness + silences, speakers, topics, moments, bad shots, cuts), the moments list, topics, speaker shares, warnings and a searchable transcript; clicking anything jumps the video there. After you add `teme`/`trenuci` and run `--provjeri`, tell the user they can open it (double-click `pregled.html`, or `python "<skill>/scripts/pregled.py" shofe_projekt --otvori` to rebuild and open it in the browser). When the user says "pokaži kartu", "otvori pregled" or "pokaži mi analizu", run that command.
   - Use the map: cut or avoid `losi_kadrovi` (blurry/dark parts), consider `tiho` segments (mic problem?) and `brzo` tempo when choosing `brzina`, and pick `hook`/`naglasi` from the best `trenuci`. When the user asks what is in the video, answer from `analiza.txt`.
6. **Plan**: `python "<skill>/scripts/plan.py" shofe_projekt --stil <style>`. It writes `edit.json` and `transcript.txt` and auto-marks retakes and filler-only segments with `"zadrzi": false`. Podcast episode or live music in the recording: run `nastupi.py` first (see "Band performances") so songs are never cut.
7. **Edit `edit.json` yourself** (this is the creative part, do it carefully):
   - Read `transcript.txt`. Verify every auto mark (`X`, `<- ponovljeno…`). For retakes keep the **last complete** take. Also drop false starts, off-topic rambling, "je l' snima?", and anything the user asked to remove.
   - Fix misheard words in `tekst` (names, brands, diacritics č ć š ž đ). Words marked `[nesigurno: …]` are the likely errors. Changing `tekst` only changes the subtitles; timing is kept. Segments marked `[rječnik: …]` were already corrected from the learned vocabulary — check them too. Your corrections are learned on render (see "Vocabulary"), so fix names consistently, word for word.
   - Add filler words to cut inside a kept segment via `"izbaci": ["eee", "ovaj"]` (only when "ovaj"/"ono" really are fillers in that segment).
   - To trim the start/end of a segment, change its `od`/`do` (seconds, source timeline).
   - `hook`: 3–7 word title for the first seconds, taken from the strongest promise/question in the video, in natural Croatian. Leave empty if the video already opens strongly and the user wants no title.
   - `naglasi`: 2–6 key words (nouns, numbers, the payoff) to colour in the accent colour.
   - Pick `stil` if the user didn't: energetic/selling → `suncani`; podcast clips → `podcast`; viral hook, short punchy → `udarno`; calm advice, explainers, YouTube → `cisto`; story/atmosphere/festival → `kino`.
8. **Look before rendering**: `python "<skill>/scripts/render.py" shofe_projekt --kadar 1,5,12` (seconds of the final video) → `kadrovi.png`. Open the image and check: face not cut off, subtitles not covering the face or the mouth, hook readable, text fits. Fix (crop, `pozicija_titlova`, `velicina_titlova`) and repeat if needed.
9. **Render**: `python "<skill>/scripts/render.py" shofe_projekt` → `reel_vN.mp4` (new version each time; the edit used is saved in `verzije/`, see "Versions"). `--brzo` gives a fast half-resolution preview; `--kvaliteta visoka` for the final YouTube upload.
10. **Report** in 3–4 lines: file path, length before → after, what was cut (segment numbers + a few words each), style. Offer the most useful next tweak, not a list.

## Commands by time in the finished video (`uredi.py`)

When the user names times they saw in the rendered video ("makni od 1:20 do 1:45", "izreži 0:05–0:08 i 1:10–1:12", "zadrži samo 0:10–0:40"), do NOT convert them to segments yourself — the finished video is cut, sped up and shifted, so its times differ from `transcript.txt`. Use:

- `python "<skill>/scripts/uredi.py" shofe_projekt makni 1:20-1:45 [more ranges]` — removes that part of the finished video.
- `python "<skill>/scripts/uredi.py" shofe_projekt zadrzi 0:10-0:40` — keeps only that part (everything else goes out).
- Times are read from the **version the user is watching**: the last render, or the version restored with `verzije.py vrati N` (`reel_vN`), so several commands in a row without a new render all use the same video. `--verzija N` if the user means an older reel; `--trenutno` to use the current edit.json (e.g. after `popis`). Formats: `1:20`, `1:20.5`, `0:01:20`, `80`, `od 1:20 do 1:45`.
- Cuts snap to whole words (a word goes out if its middle is inside the range) and are written to `edit.json` → `izrezi` (source seconds, with the command and the removed text). It prints the removed words and the new length: read them and tell the user in one line what was removed („…prve riječi … zadnje…“). If the cut leaves a broken sentence (it prints notes when a time falls inside a word), suggest extending it to the sentence end.
- Add `--proba` to preview without changing anything (use it when the user's range looks odd, e.g. very long).
- `python "<skill>/scripts/uredi.py" shofe_projekt popis` — finished-video timeline: each kept segment with its times and text, plus the time cuts. Use it to answer "što je na 1:20?" or to check a range before cutting.
- `python "<skill>/scripts/uredi.py" shofe_projekt vrati` — undo the last uredi.py command (repeat to go further back; history is in `povijest/`). For a whole render version use `verzije.py vrati N` (see "Versions"); never copy files in `verzije/` by hand.
- Then render (`render.py`, or `--kadar` first if the cut is near the hook). `plan.py --prepisi` starts from scratch and drops `izrezi`.

## Commands by content (`uredi.py` with quotes)

When the user describes WHAT to cut or keep ("izreži dio gdje pričam o cijeni", "makni rečenicu o suboti", "zadrži drugi pokušaj", "zadrži samo savjet o filteru", "vrati dio o održavanju"), **you** find the part in `transcript.txt` (and `analiza.json` topics), then let the tool cut by exact words — never edit `odsjecci`/`izrezi` by hand for this:

- `python "<skill>/scripts/uredi.py" shofe_projekt makni --od "Prvo, koliko košta" --do "tristo eura."` — from the first quote to the end of the second (quotes copied verbatim from transcript.txt, 2–5 words each; the end is searched after the start). Without `--do` the quote itself is the selection.
- `--cijele-recenice` extends the selection to whole sentences. Use it whenever the user talks about a sentence/part/topic, not specific words.
- `--tema "održavanje"` or `--tema 4` — a whole topic from `analiza.json` `teme`. `--odsjecak 5-7,9` — segment numbers from transcript.txt. `--rijeci 40-62` — word numbers from `trazi`. Several selectors add up.
- Commands: `makni` (out of the video), `zadrzi` (only this stays; it also brings back words that were cut), `dodaj` (put back a cut part: a dropped retake, a removed topic — the segment is switched on and earlier cuts over it shrink).
- "zadrži drugi pokušaj" = two commands: `dodaj --od "<start of take 2>" --cijele-recenice`, then `makni` the take that was kept (check transcript.txt: `X` segments are dropped takes).
- `python "<skill>/scripts/uredi.py" shofe_projekt trazi "cijena"` — where a word/phrase is said: word number, source time, time in the last rendered video, segment, context, and whether it is currently cut. Use it when unsure.
- Matching ignores case, punctuation and diacritics and accepts other forms of a word (cijena/cijenu) and small ASR errors; your corrected `tekst` in edit.json is searchable too. A quote that is not in the transcript is an error with the closest matches — never guess, re-read transcript.txt. If a quote occurs more than once it lists all with times: add words or `--pojava N` (ask the user only if the request itself is ambiguous).
- Read the output: it prints the selected text, every part that goes out / comes back with its time in the finished video, notes when a selection starts or ends mid-sentence, and the new length. Tell the user in one or two lines what went out or came back. `--proba` first when the selection is large (a whole topic) or you are unsure. `vrati` undoes it like any uredi.py command.

## Shorten to N seconds (`uredi.py skrati`)

"Skrati na 60 sekundi", "neka bude ispod minute", "skrati za 15 s", "treba mi verzija od 30 s": the tool drops the least important **whole thoughts** (never half a sentence) until the finished video fits, and measures the real finished length (style cut margins, `brzina`) so the result is ≤ N.

1. `python "<skill>/scripts/uredi.py" shofe_projekt skrati 60 --proba` — prints every thought (misao) in the current video: number, time in the current video, length, importance 1–5 with the reason, `X` = would go out, `^` = cannot stay without the previous one. Thoughts already respect sentence ends, question + answer, "Drugo, ugradnja." + what it announces, and sentences starting with "A/Ali/Zato/To/Još…" (kept only together with the one before). Automatic importance uses `analiza.json` `trenuci` (ocjena), how central a thought is to the whole video, and a bonus for the opening and the closing line — it does not understand the content.
2. **You rate the thoughts** — always, unless the video has only a few thoughts and the automatic result is clearly right. Read the list and give every thought 1–5 for THIS video: 5 = hook / main point / the thing the user asked to keep, 4 = strong support, call to action, 3 = useful, 2 = filler-ish, 1 = repetition, aside, tangent. Respect what the user said ("glavno je cijena" → cijena 5). Then run for real:
   `python "<skill>/scripts/uredi.py" shofe_projekt skrati 60 --ocjene "1:5,2:2,3-5:4,6:1,…"`
   - `--obavezno "verbatim quote"` (repeatable) — must stay no matter what (e.g. the user said "ali ostavi dio o garanciji"); `--nebitno "quote"` — goes out first.
   - `skrati 1:00`, `skrati na 45`, `skrati za 15` (shorter by 15 s) all work. It only removes; it never brings back parts that were cut before (use `dodaj` for that).
3. Tell the user in two or three lines what went out (by topic, not a list of every sentence) and the new length. If it says the result is clearly shorter than the target, thoughts were too long to fit — offer a higher target or a different rating. `vrati` undoes it; then `render.py`.

## Clips for social media (`isjecci.py`)

"Napravi isječke iz epizode", "predloži 5–10 klipova za Instagram/TikTok/Shorts", "nađi najbolje dijelove": Shofe finds candidates of 20–60 s in a longer recording, **you** rate them, the user picks, Shofe renders the picked ones in one batch (step 6).

1. Prepare as for any video (prepare, transcribe, `govornici.py` if more people talk), then `analyze.py` **and write `teme` + `trenuci`** (step 5 above) — the moments are the strongest signal for picking clips. For vertical clips from landscape footage prepare in 9:16 and run `kadar.py` (step 4b) so every clip shows whoever is talking.
2. `python "<skill>/scripts/isjecci.py" shofe_projekt` → `isjecci.json` + readable `isjecci.txt`. It splits the talk into whole thoughts, tries every run of whole thoughts that lasts 20–60 s after pauses are cut, scores each 0–10 (strong start: question, number, addressing the viewer, strong words, a pause before, a `hook`/`emocija` moment at the start; rounded end: sentence end, the thought does not continue, no goodbye, no long silence or topic change inside; content: your `trenuci`, density of content words; energy: loudness, tempo, little silence; 25–45 s ideal) and keeps the best 10 that do not overlap (`--broj N`, `--min`/`--max` seconds). A clip never starts with a sentence that needs the previous one ("A…", "To…", "Zato…"). Exit code 1 = waiting for your ratings. It prints every candidate with its full text.
3. **Rate every candidate** in `isjecci.json` (do not skip — the heuristic does not understand content): `"ocjena"` 1–10 (9–10 would post as is, 7–8 good, 5–6 so-so, ≤4 no), `"razlog"` — ONE Croatian sentence why it works or not on its own, and when ≥ 7 also `"naslov"` (3–6 words) and `"hook"` (3–7 words for the first seconds, like a reel hook). Judge: does the first sentence make people stay, is it understandable without the rest of the episode (no "kao što sam rekao", unknown "on/ona"), is there a payoff/emotion/useful tip, does it end cleanly. The text is the raw transcript — misheard words do not lower the rating.
   - Better bounds: `isjecci.py shofe_projekt dodaj --od "verbatim start" --do "verbatim end" --umjesto K3` (snaps to whole sentences, keeps id/title; rate it again). You may also change `od`/`do` seconds by hand; the check snaps them to whole sentences.
   - A strong part Shofe missed: `dodaj --od … --do …` (new id, `izvor: claude`).
4. `python "<skill>/scripts/isjecci.py" shofe_projekt provjeri` — checks ratings (exit 1 + list of what is missing), sorts by your rating (Shofe's score only breaks ties), warns about overlaps, length outside 20–60 s, a reason longer than one sentence, a long hook; rewrites `isjecci.txt`.
5. Tell the user the list: for each clip id, time in the recording, length, your rating and the reason (best first, 5–10 lines), and that the full texts are in `isjecci.txt`. Then:
   - "uzmi K1 i K3", "ovaj mi se sviđa": `isjecci.py shofe_projekt odobri K1,K3`; "K2 ne", "ovo ne": `odbaci K2 [--razlog "user's words"]`; `vrati K2` = back to proposal.
   - "daj još", "nađi nove": `isjecci.py shofe_projekt novi [--broj 5]` (never overlaps existing or rejected ones), rate the new ones, `provjeri`.
   - `popis` prints the list with full texts without failing on missing ratings. `predlozi --ponovo` starts over (drops ratings and picks — only when the user asks).
6. **Render the picked clips** ("napravi odabrane isječke", "napravi K1 i K3", "renderiraj isječke"): needs `edit.json` (run `plan.py --stil podcast` and review it as in "First edit" step 7 if the project has none — your text corrections, `izbaci` fillers, dropped retakes, style, music, `naglasi` apply to every clip). Every clip must have a `hook` (write one for each picked clip that has none, 3–7 words, from its first sentence/promise).
   - Podcast project (`rezija.py`): clips are 9:16 from the original cameras automatically — see the podcast section.
   - Look first: `python "<skill>/scripts/isjecci.py" shofe_projekt render K1 --kadar 1,15` → `isjecci/K1_kadrovi.png` (seconds of the clip). Check hook, subtitles, face.
   - `python "<skill>/scripts/isjecci.py" shofe_projekt render` → all **approved** clips (`render K1,K3` = these, even if not approved). For each: a separate edit (copy of edit.json, everything outside the clip cut, the clip's `hook`; main-video `izrezi` from uredi.py are NOT carried over — it prints a note when one fell inside) rendered like a reel → `isjecci/K1_<naslov>.mp4` + `.srt` + `.fcpxml` + `.edit.json`, and `isjecci/pregled.png` (first second with hook + middle of every clip). Main `edit.json`, versions and `reel_vN` are untouched. Prints every clip's length and notes like "odsječak #45 isključen u edit.json (ponovljeno…)" — if that segment is needed in the clip, switch it on in edit.json (`"zadrzi": true`) and render that clip again.
   - Per-clip settings in `isjecci.json` (any of `stil`, `naglasi`, `boja`, `velicina_titlova`, `pozicija_titlova`, `zoom`, `glazba`, `glazba_glasnoca`, `brzina`, `hook_trajanje`, `titlovi`) override edit.json for that clip ("K2 u stilu udarno" → `"stil": "udarno"` on K2). `--stil X` = one style for this whole batch. To drop a sentence inside a clip add `"izrezi": [{"od": s, "do": s}]` (recording seconds from transcript.txt) to that clip. `--brzo` = half-resolution preview (`…_pregled.mp4`), `--kvaliteta visoka`, `--bez-hooka` only if the user wants no title.
   - Open `isjecci/pregled.png` and check it, then tell the user: folder, each clip id, length, file name; offer the next tweak (usually: texts for posting, see below). Changing a clip's `naslov` renames its file on the next render (the old one is removed). Changing `od`/`do` drops the old render info; render it again.
   - Landscape project → it warns that clips come out landscape; for Reels/TikTok/Shorts prepare in 9:16 and run `kadar.py` first.

## Texts for posting (`objava.py`)

"Napiši opis za Instagram", "tekstovi za objavu", "hashtagovi", "naslov za YouTube": **you** write a caption, hashtags and (YouTube) a title for every network separately; the tool gives you the context, checks each network's rules and writes a ready-to-copy file. Never post anything yourself.

1. `python "<skill>/scripts/objava.py" shofe_projekt` (the reel the user is watching) / `… isjecci` (every rendered clip) / `… K1,K3` / `… v2`. It creates `objava.json` with, per video: what is said (from the video's `.srt`), the hook, the clip title and your reason, and empty fields `videi → <id> → mreze → instagram {opis, hashtagovi}`, `tiktok {opis, hashtagovi}`, `youtube {naslov, opis, hashtagovi}`. Networks: vertical/square ≤ 3 min → all three (YouTube = Shorts); 16:9 or longer → YouTube only; `--mreze instagram,youtube` to choose (remembered). Exit 1 while something is missing or breaks a rule.
2. **Write the texts** in `objava.json` — Croatian, the user's voice (ti-forma, casual, no corporate tone), correct diacritics, names spelled as in the corrected subtitles. Different text for each network (the tool warns when they are the same):
   - **Instagram** `opis`: first line = the hook of the post (≤ 125 characters, that is all people see before "više") — a promise, question or surprising fact from the video, not the video's title repeated; then 1–3 short sentences with the concrete takeaway in plain searchable words (Instagram search reads captions: say "čišćenje klime", not just "ovo"); end with one call to action that fits (spremi, pošalji nekome tko…, napiši u komentar…). 0–2 emoji. `hashtagovi`: 3–5 in total, specific beats generic (#ciscenjeklime over #video), mix topic + local (#kutina, #moslavina) — Instagram and TikTok allow **at most 5 per post, including the series' fixed ones**.
   - **TikTok** `opis`: shorter, 1–2 lines, keywords people would type into TikTok search, often a question that invites comments. 3–5 hashtags (same limit of 5).
   - **YouTube** `naslov`: ≤ 60–70 characters, the searchable topic first ("Kako očistiti filter klime u 2 koraka"), curiosity without lying, no ALL CAPS, no `<` `>`. `opis`: 1–3 sentences with keywords (+ what the viewer learns); `hashtagovi` 1–3 (the first 3 appear above the title; `#shorts` optional).
   - Never invent facts: prices, numbers, dates, phone numbers, promises only if they are said in the video or in the series signature (the tool warns about numbers not heard in the video — check each one). No clickbait the video does not pay off. Hashtags without spaces/hyphens; Croatian hashtags are usually written without diacritics (#suncaniput) — the tool warns, decide per tag.
   - Do not repeat the series signature or its fixed hashtags: the tool appends them.
3. Run the same command again: errors (too long, > 5 hashtags, missing field, placeholder like `[cijena]`) → fix and rerun; warnings (long first line, unheard number, same text on two networks, diacritics in a hashtag) → fix unless there is a reason. When clean it writes `<video>.objava.txt` next to the video (e.g. `isjecci/K1_….objava.txt`: each network's final text between lines, with character and hashtag counts) and `objava.txt` in the project (all finished videos). `--ispis` prints them. Tell the user the file name and show the Instagram caption in the chat; ask if the tone is right.
4. If the video is re-rendered with different speech, the next run warns that the texts may mention something that is gone: reread them.

**Series** (the user's fixed signature, hashtags and tone, kept across projects in `%LOCALAPPDATA%/Shofe/objava_serije.json`): "uvijek dodaj #sfklima i #kutina", "na kraju SF klima napiši …", "za Sunčani4M piši opuštenije":
- `objava.py serija "SF klima" --hashtagovi "#sfklima,#kutina" --potpis "SF klima Kutina · montaža i servis klima" [--mreza youtube] --napomena "tone, audience, usual call to action"` (at most 3 fixed hashtags; `--mreza` = signature only for that network, e.g. a link on YouTube; `\n` = new line; `--potpis ""` removes it). `objava.py serija` lists them, `--brisi` deletes one.
- In a project: `objava.py shofe_projekt --serija "SF klima"` (remembered in `objava.json`; `--serija ""` = none). Pick the series from the video's content (SF klima savjeti, Sunčani put, Sunčano AJMO!, Sunčani4M) and ask once if unsure; when none exists yet, ask the user for the signature and fixed hashtags before creating it. Read the series' `napomena` before writing.

## Thumbnails (`naslovna.py`)

"Naslovna sličica", "napravi naslovnu", "thumbnail", "cover za reel": Shofe picks the best frame, **you** pick the words and check the result with your own eyes. Never post anything.

1. Write the thumbnail text first: **2–5 words**, ALL the punch, not the title repeated (the title/caption already says the topic): a number, a result, a question or a bold claim that the video pays off ("FILTER U 2 KORAKA", "*80 €* BAČENO?", "NIKAD OVO NE RADI"). Mark 1–2 key words with `*zvjezdice*` → they get the style's accent colour. No invented numbers (same rule as captions). Default without `--tekst` is the video's hook (warns when it is long).
2. `python "<skill>/scripts/naslovna.py" shofe_projekt [K1 | isjecci | v3] --tekst "FILTER U *2 KORAKA*"` (no target = the reel the user is watching, else all rendered clips; `--tekst` needs one video). It scores frames of the finished video (from `source.mp4`, no subtitles/hook, the style's colour grade) every 0.5 s: face size, sharpness, eyes open (compared with the same face elsewhere in the video), light, frontal face, face not at the edge, + a small bonus inside `analiza.json` `trenuci`. Writes next to the video: `<video>.naslovna_9x16.jpg` (1080×1920 cover for Instagram/TikTok/YouTube Shorts; face and text inside the middle 3:4 that Instagram shows on the profile grid, text away from the top 14 % and the bottom 35 % where the apps draw buttons), `<video>.naslovna_16x9.jpg` (1280×720 for YouTube; from the original landscape clip when there is one — zoomed on the face, text on the other side — otherwise the vertical frame on the right with a blurred copy behind), `<video>.naslovna_kandidati.jpg` (6 best frames with number, score, time and why) and `<video>.naslovna_pregled.jpg` (both thumbnails; red dashes = Instagram grid crop). Choice and text are kept in `naslovna.json`.
3. **Always open `…naslovna_pregled.jpg` and `…naslovna_kandidati.jpg` (Read the image) before telling the user.** The eye/expression check is a heuristic: if the face looks odd (eyes half closed, mouth mid-word, motion blur), pick another candidate with `--kadar N`, or a moment you know is good with `--vrijeme 0:12.5` (seconds of the finished video). The chosen frame and text are remembered, so `--tekst` alone keeps the frame and `--kadar` alone keeps the text. `--bez-teksta` = clean frame. Read and act on `Upozorenje` lines (text over the face, face outside the 3:4 grid, no face, text too long).
4. Tell the user the two file names and what is on them (frame time, text); offer another frame or text. `objava.py` lists the thumbnail files in `<video>.objava.txt`. Uploading: Instagram/TikTok "Uredi naslovnicu → Dodaj iz galerije", YouTube Studio → Sadržaj → video → Sličica → Prenesi (Shorts too, 9:16).

## Podcast: sync cameras and separate audio (`sinkro.py`)

Sunčani4M and other multi-camera recordings: 2–3 cameras (phones, Insta360, GoPro) plus maybe a separate recorder/lav audio, started at different moments. "Sinkroniziraj kamere", "spoji kamere i zvuk", "ovo su snimke epizode": sync them **by sound** — no clap, no timecode, no manual work.

1. `python "<skill>/scripts/sinkro.py" "<folder with the episode's files>" --out podcast_projekt` (or list the files). The **main source** (the episode's timeline, 0 = its start) is the separate audio file if there is one (best sound; the longest audio file), else the longest video; `--glavni name` picks another (e.g. when the separate recorder was started late and missed the beginning). Several files from the same camera (split recordings) are fine: each file is synced on its own.
2. It writes `sinkro.json` (per source: `pomak` = where the file's 0 s lies on the main timeline, negative = started earlier; `brzina` = the camera's clock vs the main one, e.g. 1.00008 = 80 ppm ≈ 0.29 s per hour; `od`/`do` on the main timeline; `sigurnost`), `sinkro.txt` (readable), `sinkro.png` (every source's loudness drawn on the main timeline — peaks must line up) and `sinkro_provjera.mp4` (10 s mosaic of all cameras with the main audio, labelled with each file's time).
   - Time in a source = (time on main timeline − pomak) × brzina. Use this mapping for anything later (multicam cut, chapters); never assume the files start together.
   - Takes ~1 s per hour of audio plus reading the files (reading the sound of a long 4K video can take a minute or two).
3. **Check**: read the printout. `visoka`/`srednja` = trust it. `niska` or `nije pronađen` = that file probably is not from this recording (another day, a test shot), has no usable sound (muted, wind only), or overlaps for less than ~20 s. Open `sinkro.png`; if the file belongs to the episode, ask the user roughly where it starts or look at the mosaic, then set it by hand: `python "<skill>/scripts/sinkro.py" podcast_projekt --pomak kamera3.mp4=-12.5` (seconds on the main timeline; marked `RUČNO`).
   - Tell the user in 2–3 lines: main source, each camera's offset in words ("kamera 1 počela je 7 s prije zvuka"), clock drift when it is ≥ 1 frame per hour, and what needs a look.
   - Another check moment (e.g. a clap or the user's concern at 12:30): `sinkro.py podcast_projekt --provjera 12:30` (only re-renders the mosaic).
4. Next: `rezija.py` (below) turns the synced project into the episode video with the camera on whoever speaks.

## Podcast: camera on whoever speaks (`rezija.py`)

After `sinkro.py`, in the same project folder. "Montiraj epizodu", "kamera neka prati onoga tko priča", "prebacuj kamere":

1. `python "<skill>/scripts/rezija.py" podcast_projekt` — first run (no `govornici.json` yet): builds `source.mp4` = the whole episode in the wide shot with the **main audio** (16:9, 30 fps; `--format`, `--fps`) and `project.json`, so the folder is now a normal Shofe project. Episode time 0 = `pocetak` on the main timeline (where audio and at least one camera exist).
2. `transcribe.py podcast_projekt`, then `govornici.py podcast_projekt --broj N` (N = people who talk, incl. a guest off camera), then name them: `govornici.py podcast_projekt --imena "G1=Marko,G2=Ivan"` (look at `analiza`/transcript to tell who is who, or ask).
3. `rezija.py podcast_projekt` again. It looks for faces in 8 windows of 15 s per camera and matches lips to who speaks: a camera with one face = **krupni** (close-up) of that speaker; 2+ faces = **siroki** (wide); no face = only a fallback. Rules: the speaker's close-up, cut 0.2 s before the first word; wide when two talk at once (≥ 0.6 s), during quick back-and-forth (≥ 3 turns shorter than 2.5 s), when the speaker has no own camera (guest), and after 3 s of silence; every shot ≥ 2 s (`--min-kadar`); a short "aha" never switches; in a long monologue a 3.5 s wide cutaway every 30 s (`--umetci nikad|rijetko|povremeno|cesto` = never/45/30/12 s; without a wide camera the cutaway is the other person's close-up); a camera that is not recording at that moment is never chosen (black only when no camera records). A vertical phone camera is cropped around the face. Rebuilds `source.mp4`; times stay the same, so transcript, speakers, `edit.json` and versions remain valid → continue as with any project (`plan.py`, `render.py`, `titlovi.py`, `isjecci.py`). Writes `rezija.json` (cameras with role/speaker, shots with reason), `rezija.txt` (readable) and `rezija.png`.
4. **Always open `rezija.png`** (Read the image): camera thumbnails with role, speaker lanes, the program strip coloured like the camera borders (white tick = cutaway). Read `PROVJERI` lines. If a camera is wrong or unknown ("NE ZNAM TKO"), fix it by hand — it is remembered for later runs: `rezija.py podcast_projekt --kamere "kamera1.mp4=Marko,kamera3.mp4=siroki"` (values: speaker name or G-id, `siroki`, `ostalo`). Use `--analiza` to only redo `rezija.json/.txt/.png` without the slow video.
5. Tell the user in 2–3 lines: which camera shows whom, number of shots and average length, how much of each person's talking is on their own camera, and anything to check. Time: the face search takes ~10–30 s per camera; the video is re-encoded once (roughly real time or faster for 1080p on a laptop CPU).
   - Wishes: "manje širokih kadrova" → `--umetci rijetko` or `nikad`; "brže rezove" → `--min-kadar 1.5`; "kamera 2 je Ivan" → `--kamere`.
   - **Clips from a podcast are 9:16 from the original cameras** (`isjecci.py … render`, nothing else to run; not cropped from the 16:9 program and no `kadar.py`). `uspravno.py` directs each clip for vertical: the speaker fills the frame from **his own close-up camera** (a vertical phone is used as is), or, without one, a crop of his face from the wide camera (slight zoom, max 1.6×); two talking at once or quick back-and-forth → **split screen** (upper = G1…, lower = the other, each from his own camera, thin dark line between); a guest without a camera → split screen of the two listening; silence keeps the shot; every shot ≥ 2 s; no wide cutaways. A camera that stops recording mid-shot is not used for a < 2 s piece — the whole shot comes from a camera that records all of it. Per clip it writes `isjecci/izvor_9x16/K1.mp4` (+ `.json`: shots, layout, camera, speaker) = only the clip's time ± 1 s with the program audio; the render reads it with the right offset, so transcript, cuts, subtitles, hook and SRT are the same as a 16:9 clip. The `.fcpxml` of such a clip is a 9:16 timeline from `izvor_9x16/K1.mp4` (keep that folder). Prints e.g. "K1: 5 kadrova 9:16: 4 × lice govornika, 1 × podijeljen kadar". Check with `render K1 --kadar 1,10` (look at the PNG: face of the right person, nothing cut off). `python "<skill>/scripts/uspravno.py" podcast_projekt K1,K3` prints the vertical shot list without rendering. `--format 16:9` = horizontal clips from the program (e.g. for YouTube). Missing `sinkro.json`/`rezija.json`/original files → it says so and renders 16:9.
   - DaVinci export of a podcast project (every render, or `davinci.py`) uses the **original camera files**, not `source.mp4`: V1 = the switched program from the original cameras (same cuts, same framing incl. the vertical-phone crop, zooms; camera audio off), one track above per camera with that camera at the same moment (disabled — the user enables a piece, or drags it down, to switch the camera by hand; tracks V2, V3… are always the same camera), the main audio (separate recorder or main camera) on the track below (role dialogue), music below that. Needs `sinkro.json` + `rezija.json` and the files where `sinkro.py` found them; otherwise it falls back to `source.mp4` and says so. `--izvor priprema` forces `source.mp4`.

## Band performances: songs are never cut (`nastupi.py`)

Sunčani4M has bands playing in the car. A song is **never cut inside** (no pause removal, no "skrati" inside it), the whole performance stays, and its sound is processed for music, not speech. "u epizodi svira bend", "nastup benda", "pjesma", "ne reži pjesmu", "makni pjesmu", "ostavi samo pjesmu":

1. For **every podcast episode** (after `rezija.py` + `transcribe.py`, before `plan.py`) and any recording with live music: `python "<skill>/scripts/nastupi.py" shofe_projekt`. First run downloads a 6 MB sound model (CED-tiny via sherpa-onnx, ~29 MB archive, once). ~10 s per hour of audio. Writes `nastupi.json` (songs P1, P2… with `od`/`do` in source time, `sigurnost`, `pjevanje`, `pljesak`), `nastupi.txt`, `nastupi.png`. A song = music clearly louder than speech for ≥ 30 s (`--min 20` for shorter songs); pauses < 6 s inside (between verses, tuning) belong to the song; applause right after it is part of it; the radio under a conversation and short jingles are **not** songs. Edges: 0.5 s before the first note, 1 s after the last chord, never over a spoken word.
2. **Open `nastupi.png`** (yellow = music, blue = speech, green = song). Tell the user in 1–2 lines: how many songs, where, how long. Fix by hand if needed (times = source time as in transcript.txt): `nastupi.py projekt dodaj 12:30-16:10 --naziv "Bend – Pjesma"`, `granice P1 12:28-16:15`, `naziv P1 "Bend – Pjesma"` (ask the user or take it from the host's announcement in the transcript), `makni P2` (not a song; a new analysis will not bring it back). Manual changes survive a new analysis. If `edit.json` exists it is updated at once (`uredi.py vrati` undoes it).
3. `plan.py` copies the songs into `edit.json` as `nastupi: [{id, od, do, zadrzi, titlovi}]` and marks them in `transcript.txt` (`♪ P1 … PJESMA`, segments inside get `[u pjesmi P1]`). `render.py` keeps each kept song as **one piece** (also the instrumental parts without words), **no subtitles** over it (`"titlovi": true` on that song in edit.json shows the transcribed lyrics — only if the user asks and the lyrics are right), audio through a music chain (only 30 Hz rumble filter and a gentle peak compressor; no noise reduction, no speech compressor — those eat cymbals and bass), crossfaded 0.25 s with the speech chain; background music (`glazba`) is silent during songs.
4. Commands: a time range covering ≥ 80 % of a song removes the whole song; a range inside a song does **not** cut it (note: "pjesma se ne reže iznutra") — speech in the same range is still cut. `uredi.py projekt makni --nastup P1` (whole song out), `dodaj --nastup P1` (back), `zadrzi --nastup P1` (only that song, e.g. for a separate song video). `zadrzi 10:00-20:00` keeps songs that the range covers at least half. Content commands (`--od/--do`) remove/restore songs lying completely between the quotes. `uredi.py popis` shows songs as `♪ PJESMA P1`. Only when the user **explicitly** wants part of a song gone ("izreži drugu strofu", "makni solo"): `makni 3:10-3:40 --u-pjesmi`. `skrati N` shortens only speech (songs stay whole; if the songs alone are longer than N it says to remove a song first). Clips (`isjecci.py predlozi`) never span a song.

## Subtitle files (`titlovi.py`)

Every render also writes `<video name>.srt` next to the video (`reel_v3.mp4` → `reel_v3.srt`): readable phrase subtitles for YouTube/Facebook/DaVinci/VLC — whole phrases, max 2 lines × 42 characters, 0.83–7 s each, broken at sentence ends and pauses, text exactly as corrected in `edit.json` (`tekst`, `izbaci`), times of the finished video (after `izrezi`, retakes and `brzina`). Hook is not included; case is as spoken (not the style's capitals). UTF-8 with BOM.

- After a render, mention the `.srt` in the report for YouTube uploads (YouTube Studio → Subtitles → Upload file → With timing). For a long 16:9 YouTube video suggest `titlovi: false` (no burned-in captions) + the SRT, so captions don't show twice.
- "napravi VTT", "titlovi za web": `python "<skill>/scripts/titlovi.py" shofe_projekt --format vtt` (or `oba`).
- "titlovi za verziju 2": `--verzija 2` (default: the version the user is watching). `--trenutno` = current edit.json before rendering (→ `titlovi_trenutno.srt`). `--ispis` prints them (use it to check text or answer questions about subtitle timing). `--izlaz ime` sets the file name.

## English subtitles (`prijevod.py`)

"Napravi engleske titlove", "prevedi titlove na engleski": **you** translate, cue by cue; the tool keeps the translations and writes `<video>.en.srt` with exactly the same times as the Croatian SRT.

1. `python "<skill>/scripts/prijevod.py" shofe_projekt` (default: the version the user is watching; `--verzija N`, `--trenutno` like titlovi.py). It writes `prijevod_en.json` in the project and lists the cues to translate (number, time, `max_znakova`, Croatian text); exit code 1 while something is missing.
2. Edit `prijevod_en.json`: fill `"en"` for every cue in `titlovi`, never change `"hr"`. Read all cues first so you translate with the whole video in mind. Rules:
   - natural spoken English as a native speaker would say it, not word for word; keep the speaker's tone (casual stays casual);
   - each cue translates what is said **during that cue** (a viewer reads it while hearing it); move a word to the neighbouring cue only when English word order needs it;
   - keep names, brands and show titles as they are (Sunčani4M, SF klima, Sunčani put, Sunčano AJMO!, Kutina, Renault 4); numbers as digits, prices as `€300`;
   - at most `max_znakova` characters (fits 2 lines × 42 and a comfortable reading speed); shorter is better than complete; optional manual line break with ` | `.
3. Run the same command again: it checks every cue (too long = error, nothing written; fast reading speed, untranslated = warning — fix them) and writes `reel_vN.en.srt` (`--format oba` adds `.en.vtt`, `--ispis` prints Croatian and English side by side). Tell the user the file name and how to upload it to YouTube as an extra language (Studio → Subtitles → Add language → English → Upload file).
- From then on **every render** also writes `<video>.en.srt` when all cues are translated, or prints `Titlovi (en): N titlova treba prevesti…` — then repeat steps 1–3 (only new/changed cues are empty; translations are matched by Croatian text, so cuts don't lose them). A cue with `"napomena": "preuzeto iz sličnog titla … — provjeri"` got the translation of a slightly different older cue (e.g. a corrected word): check it, fix `"en"` if needed and delete `napomena`.
- Other languages: `--jezik de` (→ `prijevod_de.json`, field `"de"`, `.de.srt`). Burned-in English captions are not supported yet (only the file).

## DaVinci Resolve export (`davinci.py`)

Every render also writes `<video name>.fcpxml` next to the video and its `.srt` (`reel_v3.mp4` → `reel_v3.fcpxml`): an FCPXML 1.10 timeline that DaVinci Resolve 18+ (free version too) imports with File > Import > Timeline. It uses the user's **original clips** (paths from `project.json`) with exactly the same cuts as the video, the same framing (landscape clips fill the 9:16 frame, shifted like `--crop-x`), punch-in zooms as Zoom, music on its own track (lane below, ducking not carried over) and markers for the style, hook title and zooms. Sound and colour stay untouched so the user can finish them in DaVinci. Subtitles: File > Import > Subtitle > `reel_v3.srt`, then drag onto the timeline.

- "otvori u DaVinciju", "izvezi za DaVinci": tell the user the `.fcpxml` and `.srt` file names and the two import steps above; say that Resolve asks to find the clips only if they were moved.
- For an older version / before rendering: `python "<skill>/scripts/davinci.py" shofe_projekt [--verzija N | --trenutno] [--ispis]` (also writes the `.srt` if missing; `--ispis` lists every shot: source file and in–out).
- Podcast projects (`rezija.py`): see the podcast section — V1 program from the original cameras, other cameras on disabled tracks above, main audio below. Tell the user: "u DaVinciju uključi kadar na traci iznad (desni klik > Enable Clip ili D) i on zamijeni kadar ispod".
- If an original clip no longer exists, the whole timeline uses the prepared `source.mp4` (already cropped, 30 fps) and the tool says so. `--izvor priprema` forces that — use it when the user reports wrong framing or frame-off cuts from mixed frame rates in DaVinci.
- With `kadar.py` (frame follows the speaker) each piece is also split where the shot switches to another person, each part with its own position (like a multicam cut). In a shot where the camera follows a moving person the timeline holds the shot's middle position (no keyframes); `--izvor priprema` gives the exact moving crop.
- Projects prepared before Shofe 0.13 have no per-clip crop in `project.json`: the default crop (`--crop-x 0.5`) is assumed; if the user had used `--crop-x`, use `--izvor priprema`.

## Revisions (no re-transcribing)

## Styles

Defined in `<skill>/styles/*.json` (Croatian keys). To make a new look the user likes, copy the closest style file to a new name and change `font` (Montserrat Black / Montserrat ExtraBold / Montserrat SemiBold / Anton, all bundled in `fonts/`), sizes, colours (`#RRGGBB`, background `#RRGGBBAA`), `nacin` (karaoke = active word lit; rijec = one big word; linija = whole line), `max_rijeci`, `otkrivanje` (words appear as spoken), `pop`, `zoom`, `boja_slike`, `rezanje` ([seconds before, seconds after] each kept phrase), hook colours, `traka_napretka`.

## Vocabulary

The vocabulary learns from corrections, so the user corrects each misheard name only once or twice:

- `<skill>/rjecnik.txt` is the base list of names/terms (shipped with Shofe; reinstalling overwrites it). The user's own data lives in `%LOCALAPPDATA%/Shofe/rjecnik.json` and survives reinstalls — never edit that file by hand, use `rjecnik.py`.
- **Learning is automatic**: every render compares your corrected `tekst` with the transcript and remembers real misrecognitions (names, brands, diacritics, capitalised names, up to 3 words → 3 words: `Fertelmes → Fertelmeš`, `esef → SF`, `sunčani četiri m → Sunčani4M`, `kutine → Kutine`). Grammar fixes (case endings like `klime → klima`, short words like `je → sam`), rewording, number formatting, removed fillers and sentence-initial capitals are NOT learned. A correction becomes **active** after it was seen twice (in one or several videos); render prints `Rječnik naučio: X → Y` — tell the user in one line.
- Active corrections are applied by `plan.py` to the new `edit.json` (`transcript.txt` shows `[rječnik: …]`; the segment gets `"rjecnik": [{"iz", "u"}]`). Check them like any other text. If one is wrong in this video, just change `tekst` back: the next render notices the revert and switches that learned correction off. Corrected names (with capitals/digits or multi-word) also go into whisper's prompt (≤ 200 tokens, base list first) so transcription spells them right.
- `python "<skill>/scripts/rjecnik.py" popis` — terms and corrections (✓ active, · waiting `viđen 1/2`, switched off). Use it when the user asks "što je Shofe naučio" / "pokaži rječnik".
- `rjecnik.py dodaj "Ime Prezime"` — a term for transcription (user: "zapamti ime X", a guest's name before transcribing). `rjecnik.py dodaj "krivo" "točno"` — a correction active immediately (user: "uvijek piši X umjesto Y").
- `rjecnik.py zaboravi "krivo"` — switch off a correction for good (or remove a term the user added). `rjecnik.py primijeni shofe_projekt [--proba]` — apply active corrections to an existing edit.json (a project planned before the word was learned). `plan.py --bez-rjecnika` plans without them.

## Troubleshooting

- `ffmpeg nije pronađen` right after installing → restart Claude so PATH updates, or run doctor again (it also searches the winget folder).
- Transcription very slow → `--model medium` or `small`; an NVIDIA GPU is used automatically if CUDA libraries are present.
- Empty transcript → the clip has no speech or the wrong language; try `--jezik auto`.
- Subtitles in a wrong font → make sure `shofe_projekt/fonts` exists (render.py copies it) and the style's `font` name matches one of the four bundled fonts exactly.
- `govornici.py` cannot download models (no internet / firewall) → it needs internet once; models live in `%LOCALAPPDATA%/Shofe/modeli` (or `SHOFE_MODELI`). Wrong speaker on a short reply ("Da.", "Točno.") is expected: under ~1 s there is too little voice; fix that segment's `govornik` by hand if it matters.
- Never delete the user's original clips; all work happens in the project folder.
